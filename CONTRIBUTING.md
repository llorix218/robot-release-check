# Contributing

Thanks for taking a look at `robot-release-check`.

The most useful contributions right now are narrow and evidence-focused:

- examples of terminology that does not match real robot delivery workflows;
- edge cases that could make R001, R002, or R003 misleading;
- small synthetic test cases;
- documentation fixes;
- focused bug reports.

Please keep the V0.1 scope intentionally small. Proposals for hosted services, robot connectors, production integrations, databases, continuous monitoring, or broad rule expansion are out of scope for this experiment.

## Reporting a useful case

When opening an issue, describe the workflow using synthetic or redacted information only. Do not include customer-confidential material, credentials, source code, proprietary project documents, or production details.

A finding in this project means the supplied evidence does not establish a relationship cleanly. Missing evidence is not proof that an activity never occurred.
